## Как организована работа (и её ограничения)

### Мой процесс
1. Я выполняю чек-лист, который составляет LLM.
2. Результаты (код, конспекты, выводы) сохраняю в репозитории с пометкой дня.
3. Только LeetCode-задачи не попадают в репозиторий, они остаются на сайте.

### Роль коуча (LLM)
- Получает отчёт о выполненном дне.
- Даёт обратную связь: что хорошо, что можно улучшить.
- Предлагает **дополнительные таски на текущий день**, если есть время и силы.
- Ждёт запроса на следующий чек-лист, если я сказал «хватит» или не ответил.

### Важные ограничения

1. **«Игрушечность» инфраструктуры**  
   Используется веб-версия DeepSeek, а не API с долгой памятью. Контекст между днями может теряться. Это осознанное упрощение.

2. **Идея не нова**  
   Это механика квестов из компьютерных игр, перенесённая в образование:  
   *«Цель → таски → обратная связь → новые таски»*.

3. **Эксперимент — для себя**  
   В первую очередь — способ автоматизировать, систематизировать самостоятельное обучение. Во вторую — посмотреть, как долго LLM может удерживать траекторию без API и памяти.

4. **Выводы (если будут)**  
   Если накопится достаточно данных (рефлексия, успехи, срывы), я поделюсь живым кейсом. Но это не обещание научной статьи.

## Что отличает этот репозиторий от обычного дневника самообучения

1. **Двойная обратная связь**  
   Я получаю оценку от LLM, исправляю ошибки — и эти правки тоже попадают в репозиторий. Видна итеративность.

2. **Чередование зон сложности**  
   Каждый день: теория (подпитка интереса) + практика (навык) + когнитивная встряска (LeetCode / математика).

3. **Система без смотрителя**  
   Никто не стоит над душой. Это проверка **внутренней дисциплины**, а не способности подчиняться внешним дедлайнам.

4. **LLM — архитектор, не исполнитель**  
   Я не прошу «напиши код за меня». Я прошу: «Спроектируй последовательность действий, чтобы я сам пришёл к решению».
